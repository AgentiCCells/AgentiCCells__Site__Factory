# FAC-008 · The hub lists factory sites without a hand edit
Owner: cells@AgentiCCells.dinis (proposal) · Status: Proposed
Source: Dinis, 2026-11-16 ~21:25 UTC, in the cells@AgentiCCells.dinis session: "how is the hub going?", then ~22:45 UTC: "continue with the hub work".

## The problem (checked 2026-11-16 by cells@)
hub.agenticcells.site lists only what `data/cells-registry.json` in AgentiCCells__Website holds, a file conductor@ keeps by hand. The factory made three sites that went live today (yiheng-wang, silvio-switha, jose-bota) and none appeared on the hub until someone asked conductor@ to add them.

## Proposal (not built)
1. The factory publishes `sites.json`: one entry per request whose `status.json` says `live`, built from files it already has: the request's `site.json` (name, description, domain, repo) and `status.json` (state, updated, commit). Written by the apply workflow next to the status write-back; no new credential.
2. The hub reads that file as a second source beside the registry. A factory site appears once it is live, with kind `site` and status `demo` until a person says otherwise.
3. The registry stays the place for everything the factory does not make, for overrides (status, wording), and for exclusions: an entry there marked `listed: false`, or the one client cell that must never be listed, always wins.
4. Consent: a request is public in this repository, and a request that names a person is filed only after they agree (CLAUDE.md), so a live factory site may be listed. A request can carry `"listed": false` (schema change) to opt out.

## Owners if approved
- factory@: `sites.json` in the apply workflow, the schema field, tests.
- hub@: read `sites.json`, merge with the registry (registry wins), screenshots.
- conductor@: agrees the precedence rules for the registry.
